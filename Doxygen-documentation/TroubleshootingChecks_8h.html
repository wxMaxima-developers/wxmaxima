Detailed Description

The checks the troubleshooting dialog runs (GH #2559), their results, and the pure helpers that interpret what the checks found.

Nothing here starts a process or opens a window, so all of it can be tested directly; the checks themselves are run by TroubleshootingRunner (the ones that need Maxima or gnuplot) and by TroubleshootingDialog (the ones that only ask wxWidgets).

wxString wxm::TroubleshootingProbeValue ( const wxString &  text,
const wxString &  key,
bool *  found 
)

The value a probe query printed, as "wxprobe-<key>=<value>" on a line of its own.

The Maxima the troubleshooting dialog starts answers each query by printing such a line among whatever else it prints (load() messages, the output of wxMathML.lisp, ...). Only a complete line counts: a value whose line end hasn't arrived yet may still be incomplete.

Parameters
textEverything Maxima has sent so far
keyThe key the query printed
foundSet to whether a complete line with that key was there

◆ TroubleshootingReport()

wxString wxm::TroubleshootingReport ( const std::vector< TroubleshootingResult > &  results)

The report the dialog copies to the clipboard, to be pasted into a bug report.

One block per check: its status, its title, and the details and hint indented below it. The status words are not translated, so that whoever reads the bug report can tell what failed whatever language it was made in.

◆ TroubleshootingSummaryStatus()

The status that sums up a section.

The most important of its checks' statuses: a failure before a warning, before a check that still runs, ... before ok. So a section is only ok once all its checks are, and a failure shows on its page even while other checks still run.
