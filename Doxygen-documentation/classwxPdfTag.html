Detailed Description

Description of a logical structure element ("tag") of a tagged PDF document.

A tagged PDF document contains, in addition to its visual content, a structure tree that tells assistive technology (screen readers, braille displays, reflowing viewers) and text extraction tools what the content means: which drawing commands form a paragraph, a heading, a figure or a mathematical formula, how they should be read aloud, and in which order.

An instance of this class describes one structure element. It is passed to wxPdfDocument::BeginTag(); every drawing command issued until the matching wxPdfDocument::EndTag() becomes the content of that element.

The structure type is one of the standard structure types of ISO 32000-1, section 14.8.4, for example

  • grouping elements: Document, Part, Art, Sect, Div, BlockQuote, Caption, TOC, TOCI, Index
  • block level elements: P, H, H1 ... H6, L, LI, Lbl, LBody, Table, TR, TH, TD
  • inline elements: Span, Quote, Note, Reference, Code, Link
  • illustrations: Figure, Formula, Form

Optional properties:

  • alternate text (/Alt): a human readable description of the content, read by screen readers instead of the content. Required for Figure and Formula elements by PDF/UA.
  • actual text (/ActualText): the exact text the content represents. Text extraction and copy & paste use it instead of the glyphs that were drawn. Useful when text is drawn with lines, with decorative glyphs or as a sequence of glyphs that does not map to the intended characters (e.g. a big square root sign assembled from parts).
  • expansion (/E): the expanded form of an abbreviation.
  • language (/Lang): the natural language of the content as a BCP 47 language tag (e.g. "en-US", "de"), if it differs from the document language.
  • title (/T): a title of the element (not read as content).
  • MathML: a MathML representation of a formula. It is embedded in the PDF as an associated file of the structure element (/AF, relationship /Supplement, MIME type application/mathml+xml), as recommended by the PDF Association's best practice guide "Math in PDF" and as done by the LaTeX tagging project. Software that understands MathML (e.g. NVDA with MathCAT) can then present the formula semantically; all other software falls back to the alternate text.

All setters return a reference to the object, so that calls can be chained:

pdf.BeginTag(wxPdfTag(wxS("Formula"))
.SetAltText(wxS("x squared plus one"))
.SetMathML(wxS("<math xmlns=\"http://www.w3.org/1998/Math/MathML\">"
"<msup><mi>x</mi><mn>2</mn></msup><mo>+</mo><mn>1</mn></math>")));
// ... draw the formula ...
pdf.EndTag();
