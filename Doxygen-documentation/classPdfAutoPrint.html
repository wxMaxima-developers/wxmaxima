bool wxPdfDocument::AddFallbackFont ( const wxPdfFont &  font)
virtualinherited

Adds a font to the list of fallback fonts.

Font fallback (also known as font substitution) is used for characters the current font has no glyph for. Without fallback such characters are rendered as blanks (or as the font's "missing glyph" symbol). With fallback, wxPdfDocument splits the text into runs, rendering each character the current font lacks with the first fallback font that contains it - similar to what wxWidgets and the operating system do when drawing text on screen. Typical use: Greek letters and mathematical symbols in a document whose main font only covers Latin script.

Fallback fonts are tried in the order they were added. If the current font is bold and/or italic, the corresponding style of the fallback font family is used if it is registered; otherwise the font as given is used.

Fallback affects text output (Text(), Cell(), MultiCell(), Write(), WriteXml(), wxPdfDC and wxPdfGraphicsContext) as well as GetStringWidth(), so that layout and rendering stay consistent. Characters the current font can show are always rendered with the current font, so documents that do not need fallback are written exactly as before.

Parameters
fonta valid font, for example as returned by wxPdfFontManager::GetFont() or wxPdfFontManager::RegisterFont()
Returns
true if the font was added, false if the font is invalid
Note
Font fallback is disabled by default.
If all fonts have to be embedded (SetEmbedAllFonts(), PDF/A-1), the same rules apply to fallback fonts as to the current font.
See also
ClearFallbackFonts(), SetSystemFontFallback()

Puts an image in the page.

The upper-left corner must be given. The dimensions can be specified in different ways:

  • explicit width and height (expressed in user unit)
  • one explicit dimension, the other being calculated automatically in order to keep the original proportions
  • no explicit dimension, in which case the image is put at 72 dpi

Supported formats are JPEG, PNG, GIF and WMF. For JPEG, all flavors are allowed:

  • gray scales,
  • true colours (24 bits),
  • CMYK (32 bits)

For PNG, the following flavors are allowed:

  • gray scales on at most 8 bits (256 levels)
  • indexed colours
  • true colours (24 bits)

but the following options are not supported:

  • Interlacing

◆ SetEmbedAllFonts()

virtual void wxPdfDocument::SetEmbedAllFonts ( bool  embedAllFonts = true)
inlinevirtualinherited

Sets whether all fonts used in the document have to be embedded.

By default TrueType, OpenType and Type1 fonts are embedded (unless embedding was disabled with wxPdfFont::SetEmbed() or wxPdfFontManager::SetDefaultEmbed()), while the 14 Adobe standard fonts and the Adobe CJK fonts are never embedded. A PDF viewer has to substitute fonts that are not embedded, so the document may look different on other systems, and archival formats like PDF/A forbid non-embedded fonts.

If this mode is enabled, fonts selected afterwards are embedded:

  • fonts which allow embedding are embedded even if embedding was disabled for them;
  • the 14 Adobe standard fonts, which every PDF reader has to provide, are left unchanged, unless a replacement was defined for them with wxPdfFontManager::SetEmbeddableFontReplacement();
  • other fonts which cannot be embedded (Adobe CJK fonts, fonts whose licence forbids embedding) are replaced by the font defined with wxPdfFontManager::SetEmbeddableFontReplacement().

If no embeddable replacement can be found for such a font, the font is used without embedding and a warning is logged (once per font and document).

This mode is implicitly enabled for documents conforming to PDF/A-1 (see SetPdfA1Conformance()). Since PDF/A forbids non-embedded fonts, standard fonts are replaced in PDF/A documents even without an explicit replacement: for Helvetica (alias Arial), Times and Courier installed metric-compatible free fonts like the Liberation fonts are used automatically (see wxPdfFontManager::GetEmbeddableFont()).

◆ SetTagged()

void wxPdfDocument::SetTagged ( bool  tagged = true)
inherited

Enable or disable tagged PDF output.

A tagged PDF document carries a logical structure tree in addition to its visual content. Assistive technology such as screen readers uses it to present the document in a meaningful reading order, to announce headings, figures and formulas, and to read alternate descriptions instead of drawings. It is a prerequisite for accessible PDF (PDF/UA, ISO 14289).

When tagging is enabled:

  • every drawing command issued between BeginTag() and EndTag() becomes content of that structure element;
  • content drawn outside of any structure element, content drawn between BeginArtifact() and EndArtifact(), and everything drawn by Header() and Footer() is marked as an artifact, i.e. as decoration that assistive technology skips;
  • the document catalog gets a /MarkInfo and a /StructTreeRoot entry, and the PDF version is raised to at least 1.7.

Tagging should be enabled before the first page is added. While tagging is disabled (the default), all tagging methods are no-ops and the generated PDF is unchanged, so applications can call them unconditionally.

For a document to be accessible, applications should in addition set a document title (SetTitle()) and display it (SetViewerPreferences() with wxPDF_VIEWER_DISPLAYDOCTITLE), set the document language (SetLanguage()), embed all fonts, and give every Figure and Formula an alternate text.

Note
Tagging content inside templates (BeginTemplate()/EndTemplate()) is not supported: the structure elements are recorded, but the template content is not linked to them. Using a template inside a structure element is fine; the template then belongs to that element as a whole. Annotations and links are not (yet) added to the structure tree.
Parameters
taggedflag whether tagged PDF should be produced
